# Lesson 26: Solution notes

The comparison is the lesson's payload: the agent's behaviour is unchanged because the tool contract (name, description, schema, small structured return) survived the transport change intact. That is MCP's actual promise, not interop in the abstract but *your* tools outliving the framework that first hosted them. The malformed-argument call should produce a comprehensible error at the server and a graceful agent recovery (a clarified answer, not a crash or an invention); where it does not, the fix is schema tightness (an enum of weekday names) rather than prompt pleading.

**What to notice.** You now own both ends of a protocol most builders only consume. The capstone does not require MCP, but any tool you build from here can be published through 26b's shape in an afternoon, which changes what "done" can mean for an automation.
